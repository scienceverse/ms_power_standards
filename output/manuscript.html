Improving the Transparency of Power Analyses Through standardised Reporting

Introduction

An important step when designing a study is to justify the sample size that will be collected. The key aim of a sample size justification is to explain how the collected data is expected to provide valuable information given the inferential goals of the researcher (Lakens, 2022). One common sample size justification when the inferential goal is to test a hypothesis is an a priori power analysis. An a priori power analysis makes explicit which effect size researchers are interested in detecting. This information is essential both when interpreting the informational value of a study, as when interpreting the test results. A study that has high power only for unrealistically large effect sizes is unlikely to contribute useful insights to the published literature. If a hypothesis test yields a non-significant result, the range of effect sizes that could have been detected with low error rates is made explicit by the power analysis, which provides important context to evaluate the test results. For these reasons, researchers need to report all parameters used to compute the power analysis.

Despite the important role power analyses play in hypothesis testing research, there are no reporting guidelines for power analyses. Furthermore, when a priori, sensitivity, or compromise power analyses are reported, researchers often omit important information (Bakker et al., 2020; Mesquida et al., 2025; Thibault et al., 2024). For example, Bakker et al (2020) investigated the transparency and reproducibility of power analyses reported in 210 preregistrations submitted to the Open Science Framework and institutional review boards proposals. In 52 (30%) of the reported power analyses, the effect size metric was not specified and in 26 (15%) the effect size magnitude was not specified. Only 34 (20%) power analyses provided enough information to reproduce the power analysis and only 62% of these power analyses pertained to the main hypothesis test in the pre-registration.

Similarly, Thibault et al (2024) assessed the transparency and reproducibility of 95 power analyses reported in published articles. They could only reproduce 2 (2%) without making any assumptions and could likely reproduce another 27 (28%) after making assumptions. For 46 (48%) power analyses, they could not determine whether the power analysis was for a statistical test that appeared in the results section of the publication. Another recurring issue was that power analyses are often based on default options offered by G*Power (i.e., assuming a medium effect size, \alpha = .05 and a power of .80) that may not be relevant to the analysis.

Finally, researchers often fail to justify the assumed effect size. For example, Mesquida et al (2025) reported that in a sample of 144 articles reporting an a priori power analysis, 48 (33%) did not justify the selected effect size. This lack of transparency prevents editors, reviewers, and readers from being able to reproduce power analyses but also critically evaluate their validity.

Complete reporting

The report of a power analysis must contain several components in order to be interpretable and reproducible.

The type of power analysis should be clear: is it calculating power from sample and effect sizes, sample size from desired power and effect size, or the smallest effect size detectable at a specific power and sample size? Is it an a priori analysis used to determine sample size before data collection for planning, or a sensitivity analysis used after data collection to help interpret findings?

The reader must be able to determine exactly which result the power analysis corresponds to, and which effect if the model estimates more than one effect. The assumed parameters of the statistical test must be clear. For example, specifying Student’s vs Welch’s t-test or the variance components of a linear mixed effects model. Also include the criteria used to determine significance (e.g., the critical alpha and any corrections applied).

The effect size should be specified with a clear metric (e.g., 0.5 Cohen’s d, not “medium”) and justified if it is not the output of the power analysis.

The total sample size should be reported explicitly, and where applicable, the sample size per group.

The power should be reported explicitly, and not assumed to be a default.

Finally, the software used to calculate power should be cited, including the version, add-on packages used, and ideally with reference to supplemental materials that contain the exact code or specifications if this is too complex to include in the text.

Automated checks

One way to improve the reporting of power analyses is by developing tools that perform automated checks and provide feedback to researchers about how to improve their reporting. Metacheck [ADD REF], a suite of tools for checking research outputs for best practices, has one such tool in the built-in power module. This module identifies paragraphs that are likely to contain a power analysis using text-matching and returns the paragraphs along with advice on the components of a complete power analysis in a report.

Extracting parameters of a power analysis from unstructured scientific text is challenging because the same information can be phrased in many different ways. Consequently, deterministic rule-based approaches fail to identify parameter information that is present but expressed in an unexpected way. To address this limitation, the power module can optionally use an LLM to interpret flexible human language and provide even more targeted advice.

To illustrate this approach, we applied the LLM-version of the power module to a sample of 1937 open-access articles from Psychological Science. Table 1 shows the proportion of missing components from 1295 power analyses. Although the LLM-based approach can identify information expressed in a wider range of ways than rule-based methods, some parameters remain missing because they were not reported or could not be reliably extracted from the text.

Although LLMs provide a flexible way to parse natural language variation, they treat the symptoms of inconsistent reporting rather than its root cause. When information is inherently ambiguous or incomplete, an LLM may misclassify a power analysis or extract incorrect parameters. Moreover, using LLMs for routine information-extraction tasks incurs substantial computational and energy costs. A preferable long-term solution is to reduce the need for LLM-based approaches by making scientific text easier to extract in the first place. This goal is best achieved through standardised reporting conventions.

To improve the way power analyses are reported in the scientific literature, we propose a two-step solution. First, we will develop standardised reporting guidelines that provide clear and universal guidance on how to transparently and completely report power analyses. Importantly, these guidelines will be structured in a machine-readable format, so that reporting standards can be consistently interpreted and applied by automated tools without relying on large language models to interpret the information. Second, we will formalise these reporting guidelines in a structured schema that specifies the information that should be reported for each component of a power analysis. This schema will be used in the Metacheck power module to validate the information reported in power analysis statements. This will facilitate the identification of missing or incorrectly reported information and provide researchers with guidance on best reporting practices.

Reporting guidelines

One reason power analyses lack key information is the absence of specific reporting guidelines that editors, reviewers, and researchers can follow. For example, the American Psychological Association’s (APA) Journal Article Reporting Standards (JARS) provides reporting standards for several aspects of scientific articles (Appelbaum et al., 2018), such as p-values and confidence intervals, but it provides no guidance on how to report power analyses. Furthermore, JARS reporting guidelines specify what information to report, but rarely provide detailed information about how the information should be presented. For example, JARS for quantitative articles state that researchers should describe the “power analysis, or methods used to determine precision of parameter estimates” but does not specify how this information should be reported. Given the importance of power analyses for the evaluation of research findings, a reporting standard that specifies both the required information and a consistent structure for how this information should be presented could substantially improve current research practices.

A useful precedent exists in the standardised reporting of statistical tests following APA guidelines. Researchers are familiar with reporting statistical tests such as t-tests and F-tests in a consistent order that includes the test statistic, degrees of freedom, p-value, effect size, and its confidence interval. For example, an F-test may be reported as F(1, 198) = 15.23, p < .001, \eta_p^2 = 0.07 90% CI [0.02; 0.14]. These standardised reporting convention allows readers to quickly identify and interpret the information they convey. At the same time, standardised reporting practices have the important benefit that they enable automated extraction of tests, which is used by tools such as Statcheck to reliably parse statistical tests and verify reported p-values (Nuijten et al., 2015).

The same approach can be applied to power analyses. The standardised reporting of power analyses should ensure that information is interpretable by human readers but also structured in a way that automated tools like Metacheck can extract using deterministic approaches (e.g., regular expressions). The extracted information can then be put in a structured format, which can be validated against a schema to ensure that all required fields are present and that reported values conform to the specified constraints.

The first step is to determine how the essential information should be reported. As explained above, a fully reported power analysis requires the type of power analysis, relevant details of the statistical test, the effect size specified with a clear metric and justification, the sample size, power, and the software used. Combining these properties in our proposed standard report for power analyses would lead to a sentence such as:

We determined sample size using G*Power 3.1.9.6 (Mac) for the interaction effect of a 2 x 2 within-subject F-test, assuming a within-participant r = 0.5 and using a critical alpha of 0.05. The effect size of interest was f = 0.12, based on the previously published study by Someone et al., (2025). With a desired power of 0.90, this returned a sample size of 186 observations.

Alternatively, and just as statistical tests are abbreviated instead of communicated in prose, one could write:

A power analysis (sample size; F-test, 2w*2w, interaction effect, r = 0.5, critical alpha = 0.05; effect size: f = 0.12, previous study (Someone et al., 2025); sample size: N = 186; power = 0.80; G*Power, 3.1.9.6 (Mac), www.figshare.com/screenshot_of_gpower) indicated that 186 observations should be collected.

Generically, the format is ordered as follows: Type of power analysis, test details, effect size, sample size, power, software. For other types of power analyses the achieved sample size is added, and the computed variables are moved to the end of the statement. For example, a sensitivity power analysis based on a simulation in R would be reported as:

A power analysis (sensitivity, R, t-test, two-sample, N = 90 (45 per group), Type 1 = 0.05, Type 2 = 0.10, www.data_repository.org/link_to_simulation_script) indicates that effects of d = 0.69 could be detected with the desired 90% power.

Structured schema

To formalize these reporting requirements and facilitate power analyses to be machine-readable, we have developed a JSON schema that defines the parameters to be reported. The schema contains the data types, permitted values, and any relationships or conditional requirements between characteristics of a reported power analysis. The JSON schema serves as a formal machine-readable specification of the reporting standard. Researchers are not expected to report power analyses in this format, but to report power analyses clearly enough such that software can parse their writing, and add it to a schema automatically (and without the use of large language models). An example of the full .JSON file is presented below, and is followed by a detailed explanation of each aspect of a power analysis that should be provided for full reporting.

Unique Identifier

We propose that each power analysis should be assigned a unique identifier. This identifier creates an explicit link between the research question, the statistical test used to address it, and the corresponding power analysis. Power analyses are often reported with insufficient detail to determine which hypothesis or statistical test they were intended to support (Bakker et al., 2020; Mesquida et al., 2025; Thibault et al., 2024) .

This issue is particularly relevant in studies that include multiple hypotheses or multiple statistical tests. Assigning a unique identifier to each power analysis establishes these relationships and determines whether each planned analysis is supported by an appropriate power analysis. Combined with statistical tests also in a machine-readable format (Lakens & DeBruine, 2021), such links could facilitate automated checks of whether all primary analyses have a corresponding power analysis. The id field should contain a unique identifier that allows the power analysis to be linked to the corresponding hypothesis and statistical test. Where researchers often list and number hypothesis (e.g., H1, H2, H3), it should be just as normal to list multiple power analyses, as each hypothesis corresponds to a unique test , with its own statistical power for an effect size of interest.

Box 3.1: JSON Schema representation of the id property.

{
  "id": {
    "type": "string",
    "description": "Unique identifier used to link the power analysis to the corresponding hypothesis and statistical test."
  }
}

Type of power analysis

There are three types of power analyses. One can calculate power from sample and effect sizes, sample size from desired power and effect size, or the smallest effect size detectable at a specific power and sample size, all given specific test parameters.

Specific terminology around power analyses can be complex and confusing. An a priori power analysis calculates sample size before data collection, given desired power, a target effect size, and specific test parameters. A compromise power analysis calculates power from sample size and effect size, varying the alpha criterion or other decision criteria to balance Type 1 and Type 2 error rates. A sensitivity power analysis calculates the smallest effect size that can be detected with desired power given a sample size and test parameters.

After data collection, researchers may also calculate the hypothetical power of a study design based on the final sample size and an assumed effect size of interest, often termed a post hoc power analysis. This provides information about the sensitivity of the study design given the sample size and can be understood as the post-data-collection counterpart of an a priori power analysis. However, the term post hoc power analysis is frequently used ambiguously. It may alternatively refer to calculating power using the effect size observed in the data, which provides no additional information beyond the p-value (Lakens, 2022; Yuan & Maxwell, 2005). Researchers have therefore recommended avoiding calculating power based on observed effect size (Lakens, 2022; O’Keefe, 2007; Yuan & Maxwell, 2005).

For clarity, we propose using effect size sensitivity for calculating the smallest effect size that can be detected with desired power, power sensitivity for calculating power given a hypothetical effect size of interest, and observed power for calculating power using the effect size observed in the data.

Due to the confusion around terminology, we propose a straightforward classification of power analyses based on what is being calculated: power, sample size, or effect size. Further distinctions between power sensitivity and observed power analysis can be determined by looking at the effect size justification (detailed in the net section).

Test parameters

Researchers should provide both general information about the family the test that power is computed for belongs to (e.g., a correlation, t-test, or F-test) and any further test parameters that will affect the power analysis. For example, for a t-test, power analysis software such as G*Power would require users to specify the type of t-test (one-sample, two-sample, or paired-sample).

For F-tests, researchers should specify the factorial structure (for example using notation such as 2w, 2b, or 2b*2w, where the number indicates the number of levels and the letters indicate within-subject (w) or between-subject (b) factors) and which effect the power analysis is for. The effect of interest must be specified because a statistical test does not always unambiguously identify the specific effect for which a power analysis was conducted. For simple designs, such as a t-test, the effect of interest typically corresponds directly to the comparison being tested. However, in factorial designs, researchers may be interested in different effects, including main effects, interactions, planned contrasts, or simple effects. Specifying the type of effect clarifies which hypothesis the power analysis was designed to evaluate and allows readers to determine whether the power analysis corresponds to the intended research question.

Some statistical tests require additional parameters to fully specify the power analysis. These test parameters depend on the test family and the design configuration. Test assumptions (e.g., the homogeneity of variances assumption that differentiates Student’s t-test from Welch’s t-test, or a Greenhouse Geisser correction for an f-test) are one example of test parameters. For correlations and t-tests, the directionality of the hypothesis should be reported using the tail parameter. For within-subject F-tests, the correlation between repeated measurements should be reported. This correlation represents the expected association between repeated observations and influences the variance estimate used in the power calculation. In complex designs, this would require specifying a correlation matrix. The more complex a test is, the more details of a test need to be specified, up to a point where it might be easier to share the code for the power analysis than to describe all details of the test verbally.

Another important test parameter is the critical alpha. Although 0.05 is commonly used as a default alpha level in hypothesis tests, the alpha level should be reported because it determines the threshold for statistical significance and directly affects the power of a test. Reporting the alpha level also allows peers to evaluate whether it matches the alpha level used in the study. For example, a study may adjust the alpha level to account for multiple comparisons in the results section, but use a different alpha level in the power analysis. As corrections for multiple comparisons lower the alpha level, the also lower the statistical power of the test. To facilitate machine readability and automated extraction, the alpha level should be reported as a numeric value between 0 and 1 (e.g., 0.05 rather than 5%). The justification property allows researchers to provide a justification explaining the rationale for this choice (Lakens et al., 2018), such as adjustments for multiple comparisons. Effect size

The effect size metric (e.g., Cohen’s d, r, or odds ratio) and magnitude (e.g., 0.5, 1.3) used in the power analysis should be reported. However, a common issue in the reporting of power analyses is that neither the effect size metric nor its magnitude are reported (Bakker et al., 2020; Mesquida et al., 2025; Thibault et al., 2024). Reporting only the numerical value (e.g., an effect size of 0.1) is insufficient because the same value can represent different quantities depending on the metric used. For example, an effect size of 0.1 could refer to Cohen’s d, Cohen’s f, or \eta_p^2 ). Reporting the metric allows readers to determine whether the assumed effect size corresponds to the effect of interest, and increases the reproducibility of the power analysis. Reporting the exact magnitude, rather than t-shirt sized like “small”, “medium”, or “large”, allows readers to evaluate whether the assumed effect size is plausible, justified, and appropriate for the research question.

Reporting the metric may not always be sufficient trace back what it was based on. Researchers may convert the effect size they use in a power analysis from an effect size reported in another metric, calculate an effect size from summary statistics, or combine multiple effect sizes in the literature to obtain the value used in the power analysis. For example, researchers may combine information from multiple studies by averaging reported effect sizes, or apply bias-adjustment methods to an effect size reported in a previous study or meta-analysis. Although this recommendation goes beyond simply reporting the power analysis, it is essential information to be able to evaluate the validity of a power analysis. Researchers should transparently report how the effect size used in the power analysis was obtained or calculated. For example, if an effect size was converted from another metric, researchers should report the original metric and the conversion formula used. If the effect size was calculated by the researchers, the calculation procedure should be described. This information allows readers to evaluate the assumptions underlying the selected effect size and improves the reproducibility of the power analysis.

The source of the effect size is important for interpreting a power analysis. There are six common approaches that researchers use to justify the effect size of interest in a power analysis: effect sizes from previous studies, meta-analyses, pilot studies, Cohen’s d thresholds, field-specific thresholds, and the smallest effect size of interest (SESOI) (Lakens, 2022). Reporting this information again goes beyond the statistical properties of a power analysis, but is essential when evaluate whether the sample size justification is valid. We therefore think that in addition to reporting how the effect size was determined, researchers should provide a justification for why this effect size was used in the power analysis.

This information is especially important to be able to detect common problems with the choice of an effect size of interest in a priori power analyses. When effect sizes are derived from previous studies or meta-analyses, researchers should explain that the effect is sufficiently similar to the planned study, as studies might differ in the population, study design, manipulation, intervention, or even outcome measures. Furthermore, researchers should reflect on the (possibly large) uncertainty in the effect size estimate of the original study. This is also true if the effect size comes from a pilot study that the researchers performed themselves.

Instead of using an empirically observed effect size for the power analysis, researchers may rely on Cohen’s d thresholds for small, medium, and large effects, or field-specific benchmarks. This practice can be problematic because it uses general benchmarks to design a specific study that is likely not similar to the general study in a field. Consequently, choosing an effect size solely on the basis of Cohen’s d thresholds or other field-specific benchmarks may overlook the contextual factors that determine whether the effect size is appropriate for the planned study (Primbs et al., 2022).

A better approach is to justify the effect size based on a smallest effect size of interest (SESOI), which specifies the effect a researcher does not want to miss, either because it is considered theoretically or practically meaningful for the research question. Regardless of the justification for the effect size is used to compute power, it should not simply be stated, but researchers should justify why it is a relevant effect size to design the study around.

Sample size

The sample size used in the power analysis should be reported explicitly. Researchers should both report the total sample size, and where applicable, the sample size per group. Reporting the total and per group sample size allows the power analysis to be reproduced. The sample size can be people, or multiple observations from a single individual, or any combination thereof, and for studies with multiple observation per individual, information about the number of observations should be provided as well.

Power

The power level should be reported because it determines the probability of detecting an effect of the specified magnitude, assuming that the effect exists. Although a power of 0.8 is commonly used as a default, researchers should explicitly report their chosen level of power, and there are good reasons to increase the statistical power 0.9 or 0.95 where possible. To facilitate machine readability and automated extraction, power should be reported as a numeric value between 0 and 1 (e.g., 0.80 rather than 80%).

Box 12.1: JSON Schema representation of the power property.

"power": {
      "type": "number",
      "minimum": 0,
      "maximum": 1,
      "description": "Planned or achieved statistical power."
    }

Software

The software used to conduct the power analysis should be reported to allow peers to reproduce the analysis using the exact same software, and where relevant, the packages package used (e.g., the specific R package). Different software packages can return slightly different calculations for the same settings. Researchers should also provide a link to the script, notebook, or other file that contains the code used to perform the power analysis. The link is preferably a Digital Object Identifier (DOI) that links to a file in a stable data repository. If the software used is point-and-click, researchers can link to a screenshot (for example on Figshare).

Discussion

Standardizing the way information is reported in scientific articles has benefits beyond improving the transparency of individual power analyses. When information is consistently structured across articles, automated tools can more reliably extract and organize reported information.

The proposed standardised reporting and schema represents an initial step toward a more transparent and clear representation of power analyses by imposing a consistent structure on the information required to evaluate and reproduce power analyses, while also facilitating information extraction using rule-based automated tools.

The current version focuses on commonly used statistical tests, including correlations, t-tests, and F-tests. Extending the standard to accommodate more complex analytic approaches, such as power analyses for mixed-effects models or simulation-based power analyses, will require identifying additional parameters and reporting requirements. Developing a comprehensive standard that covers the diversity of power analysis approaches used across disciplines will therefore require a community effort involving researchers and other stakeholders, such as journals. Such collaborative development can ensure that future extensions of the schema reflect the needs of different research communities while maintaining a consistent structure that supports both human interpretation and automated extraction. Future developments could also explore workflows in which software generates machine-readable representations directly, reducing the need for manual data entry while preserving the advantages of structured reporting.
